# Skull King Tavern — web client

Vite+ (`vp`), React 19, strict TypeScript. The rules for this folder are in
`docs/agent-rules/web-quality.md`.

```bash
npm ci
npm run dev        # http://localhost:5173 — proxies /api to the Rust server on 127.0.0.1:8080
npm run check      # format, lint and types (vp check); `npx vp check --fix` formats
npm run test       # vp test
npm run build      # vp build
npm run fixtures:check   # the files in fixtures/engine are what the reference produces
```

Node 22.18+, 24.11+ or 26+. Vite+ warns on other versions.

## Layout

| Path                                   | What it holds                                                                                                                                                         |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/game/`                            | The reference engine: rules, reducer, bots. Runs the offline modes. Online, the server's engine is the authority and this one is never asked.                         |
| `src/table/`                           | `Table`, the seam between the renderer and whoever runs the game. `LocalTable` is the offline one; the socket client will be the other.                               |
| `src/tableview/`                       | The table renderer, lifted from the legacy build. It owns `#app` and rebuilds it from HTML strings; React never renders inside it. `mountTavern()` is its only entry. |
| `src/sound/`                           | Sound. Every effect is synthesised with Web Audio; the played card also has recorded takes in `samples/`.                                                             |
| `src/styles/`                          | `tokens.css` (the custom properties) and `tavern.css` (everything else).                                                                                              |
| `src/protocol/generated/`              | Wire types, generated by `skt-protocol`. Never edited by hand.                                                                                                        |
| `scripts/generate-engine-fixtures.mjs` | Records `fixtures/engine/` from `legacy/Skull King Tavern.html`.                                                                                                      |

## What keeps the port honest

- `src/game/engine.fixtures.test.ts` replays every game in `fixtures/engine/`. The Rust engine
  replays the same files.
- `src/game/reference.test.ts` runs the legacy engine next to this one: the seeded shuffle, whole
  bot games decision by decision, and the scorekeeper's scoring.
- `src/tableview/parity/` runs the legacy page's own script next to the lifted renderer and compares
  markup, storage, animation calls, Web Audio calls and vibration step by step, through a solo game,
  pass-and-play, the scorekeeper and every sound. The test page loads no recorded takes, so what is
  compared is the synthesiser.

The legacy file is the reference for all three. It changes only when the rules change on purpose,
together with the pinned hash in the fixture generator.

## Deliberate differences from the legacy page

- No `window.SKT`. Tests import the modules.
- Fonts are bundled (`@fontsource`), not loaded from Google.
- The renderer can be taken off the page again: `mountTavern()` returns a cleanup that removes every
  listener, timer, banner and the sprite. State is read from storage at mount, not at import.
- A seat colour is put into a `style` attribute only if it is a six-digit hex value (`cssColor`).
- The prefixed `webkitAudioContext` of Safari before 14.1 is not used.
- A played card sounds one of four recorded takes ([Recorded sounds](#recorded-sounds)). The legacy
  page synthesised it. That recipe is still there: it plays until the takes are loaded, and for good
  if they cannot be.
- States the legacy code could not reach but would have crashed on (no pending ability, no last
  trick) render nothing instead.

## Recorded sounds

`src/sound/samples/` holds the takes, `src/sound/samples.ts` fetches them at startup, and
`Sound.samples()` hands them to the mixer. A sound with takes plays one of them, never the one it
played last, a little faster or slower each time (up to 6 %). `src/sound/sound.test.ts` covers that
and the fallback to the recipe.

- `card-play-a.wav` to `card-play-d.wav` were generated on 2026-10-11 with ElevenLabs Sound Effects
  v2 (`eleven_text_to_sound_v2`): one hit from each of the four variations it made for the prompt
  "Single playing card slapped down onto a wooden table, crisp papery snap with a soft woody thud,
  close-mic, dry". Using them is subject to the ElevenLabs plan they were generated under.
- Each was cut to the hit (0.19 to 0.24 s long, the slap 35 to 50 ms in), faded in over 4 ms and
  out over 30 ms, and stored as 16-bit mono WAV at 44.1 kHz: every browser decodes it and it starts
  on the first sample.
- Each is stored so that its loudest 60 ms has an RMS of 0.05. The synthesised `cardPlay` recipe
  renders about 0.058 there, so the takes play at a gain of 1.

## Carried over as it was, to fix on purpose later

These are behaviors of the legacy page that look like bugs. They were ported unchanged so the lift
stays a lift; each fix should come with its own test.

- A table update that is waiting on a banner continues after its table was replaced: starting a new
  game within about a second can briefly show the old one.
- An error thrown while an update is presented is only logged, and can leave game input locked.
- During the 190 ms closing animation of a sheet, a table update can re-render it; the action then
  runs against a stale element.
- "No saved game" and "no scoresheet" are stored as the string `null` instead of removing the key.
- The one-time swipe hint is marked as shown inside a view function, so an early re-render drops it.
- Escape closes a sheet without the closing animation or sound.
- `tavern.css` still carries the legacy's literal colours next to the tokens. New code uses tokens
  only; the old rules move over as their screens are touched.
